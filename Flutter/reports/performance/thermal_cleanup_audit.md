# 手机发热风险与文件缩减审计

## 范围与证据边界

- 修改范围仅限 `Flutter/`，不修改后端、不连接或变更服务器。
- 从移动端 `main.dart`、路由、Provider、共享包和原生录音桥梳理引用与生命周期；
  清理前移动端有 430 个 Dart 源文件。保留任务开始前已有的本地修改。
- 本次是静态代码审计和小范围自动化回归，不是物理设备温度/耗电实测。
  不能据此声称降低了多少摄氏度或多少电量。

## 逐项处置

| 部分 | 发现与处置 | 保持不变的边界 |
| --- | --- | --- |
| 数字孪生粒子人 | 原脉冲每帧构建 `CustomPaint`，重算、排序同一批最多 964 个三维点；改为 `CustomPainter` 直接监听动画，并缓存当前投影、深度色和基础半径 | 模型种子、数量、脉冲/融合公式、拖动、缩放、重置、宽屏和窄屏 UI 均保留 |
| 录音处理取消 | 原每个详情投影等待器每 25 ms 检查取消；改为 token 取消通知，等待期间无周期检查 | 不取消共享读回，不重发服务端任务；回执、重试、超时和投影单飞保持 |
| 诊断日志 | 原生产 logger 只合并同一微任务前的日志；现前台使用固定一秒上限和原 20 条阈值合批，离开前台/后台新事件/销毁立即刷写；同时消除异步存储失败后自行重新排入微任务的无间隔重试链 | 脱敏、即时查询叠加层、错误、关键录音/上传/ASR 诊断和持久化失败可观测性保留 |
| AI 喂养图谱 | 已有路由/标签/前后台门控、30/15 FPS 温控、减少动态效果和复用投影缓冲；不替换为静态图片，不删除现用图谱 | 拖拽、缩放、节点点击、语义边、真实三维图谱与大数据集覆盖保持 |
| 音频采集/波形 | 原生采样计时器已要求录音状态和事件订阅；波形监听随消费方注销，采样在原生工作队列执行 | 不降低音频采集/ASR 质量，不停止必要的后台录音，不动录音归属和持久化恢复 |
| 网络轮询/恢复 | 现用轮询器已有单飞、取消、前台门控、退避和截止期限；每日话题前台检查有功能用途 | 不擅自延长协议轮询、删除推送、恢复、同步和鉴权 |
| 桌面小组件/图片/数据库 | 已有快照去重/合并、资源缓存、后台写入和容量治理；保留这些实际使用的能力 | 不将常驻服务或测试专用辅助文件仅凭名称判定为无用 |
| 动效和玻璃 UI | 现有 route、TickerMode、Reduce Motion 门控保留；持续可见的动效仍有渲染成本 | 不通过取消可见功能或全局降低画质掩盖问题 |

后端只读核对：`source/internal/api/routes/recording_routes.go`、
`source/internal/services/recording_service.go` 及对应 SCM 协议；录音详情仍通过
鉴权的用户归属查询聚合得到，本次仅更换 Flutter 等待取消机制。

## 验证与数量

### 实际文件缩减

- `Flutter/` 本地目录从审计开始时约 10 GiB 降至约 **265.4 MiB**。
- 删除 **3,775 个已受 Git 跟踪的文件，原内容合计 387.39 MiB**；绝大多数
  是交接副本、ZIP 和误跟踪的 iOS 编译产物，不是数千个业务模块。
- 可重建编译缓存本次清理 **10,878 个文件**，按文件逻辑大小合计 **9.63 GiB**
  （`du` 目录计量约 9.66 GiB，其中也包含本次验证生成的缓存）。该数字不是
  APFS 实际可用空间增量，也不是安装包缩减值。
- 另清理 16 张未跟踪的失败对比图与两份 Finder 元数据文件。源码、工作区依赖
  解析配置、锁文件、原生 SDK、业务资源及现有/并行进行的用户修改均保留。
- `.git` 历史没有重写；下一次构建将正常重新生成缓存。

### 聚焦验证

- 核心回归 **93 项通过**：任务取消、日志合批/失败恢复、录音处理、投影缓存和 part 引用。
- 另行执行的图谱/主题检查为 **30 项通过、1 项既有失败**。现用图谱四组
  节点/边场景（100/200、250/500、500/1500、500/3000）均通过。
- 移动端源码可达性 **423/423**；三个数字孪生 part 保持可达，没有删除它们。
- SCM/源码树检查通过；最终 `dart analyze lib` 为 **0 error、0 warning**，
  仍有 341 个 info 级建议，未扩大为全项目风格改写；`git diff --check` 通过。

### 明确保留的问题

- 主题约束失败指向 `v3_digital_twin_page.dart` 和 `v3_digital_twin_materials.dart`
  中固定黑白色。与 Git HEAD 对比，命中数分别仍为 2 和 1；本次没有新增这些
  固定颜色，也没有放宽测试例外或改变界面外观来让测试通过。
- 整体架构门禁仍报告既有超长模块、RFC/常驻 Provider 标记及其他债务，并非全绿。
  按“规则类别 + 文件”对照，问题从 81 类减少至 69 类，没有新增类别；未调高预算。
  新增取消等待能力后，将只读调度快照/错误值归入现有模型文件，使调度器仍满足
  500 行上限，而非放宽该上限。
- 温度、功耗、电池续航、真机 Profile 帧时间：**未测量**。未使用模拟器温度替代
  真机证据，也未为了清理而停止录音、降低 ASR 质量或取消现有交互。

## 2026-09-08 二次复查

复查基线为 `d34fcd2d7`。上一轮清理已进入当前版本，本轮继续沿用；发现的录音卡
原生端口及其契约测试的其他工作区改动不覆盖、不计入本轮优化成果。

### 本轮新增修复

| 问题 | 优化 | 功能边界 |
| --- | --- | --- |
| 性能监控被帧通知反复创建 | runtime 依赖帧收集器的 notifier 身份，而非每次帧样本通知；避免重复安装生命周期/任务监听和重置启动计时 | 首帧、首次可交互指标保持；真实依赖替换仍可重建 |
| 性能策略计算与下游刷新过多 | 总帧 P95 使用按样本失效的不可变缓存；策略只观察前台、电源、减少动态效果、内存压力与帧质量档位，忽略路线/标签/网络元数据和同档位数值波动 | 17/24 ms 原阈值、图谱温控、恢复延迟和任务并发预算不变；完整诊断仍可导出 build/raster/total |
| 录屏事件监听无法随最后一个订阅释放 | 移除平台广播流外多余的 `asBroadcastStream` 包装；最后一个监听退出后触发原生 cancel，后续监听可重新连接 | 不发 stop/release 指令，不停录屏，不动原生会话 watchdog、恢复、媒体校验或导入 |
| 隐藏录音卡仍每秒刷新时长 | 时长显示同时受 TickerMode 和当前路由可见性约束；隐藏时取消显示计时器，返回后从原录音时间戳显示 | 不暂停实际录音，不改变录音时长归属，不新增设备状态轮询 |

另移除 runtime 模块中被 widgets 导出覆盖的多余 painting import。该历史审计不定义当前开发流程。
