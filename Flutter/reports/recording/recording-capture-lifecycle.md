# 外录与内录：生命周期整理

> 历史审查与验证记录：以下测试数量、设备状态和修复结论均对应原记录时点，
> 不代表本次目录整理执行了硬件、服务器或全量回归验证。

## 外录真机入口失效：依赖身份修复

### 真机证据与历史

- 使用已连接的物理 iPhone 11（设备标识末尾 `7A802E`），未使用 Simulator 替代。
  `devicectl` 确认开发者模式启用、设备已配对且解锁；运行中的 Runner 进程为 54443。
- 完整复制 `Documents/recordings` 的 SQLite、WAL、SHM 后只读查询。持久化诊断中没有
  外录入口/初始化的阶段记录，这是可观测性缺口，不能据此认定用户没有进入外录。
- 通过真机 Flutter 附加连接及 Dart VM 只读对象检查，确认当前外录页
  `_entryReady=true`，错误为“录音入口已被更新，请关闭后重试”。旧控制器已销毁，
  状态停在 `loadingSources`、journeyRevision 为 2；替代控制器仍为未初始化的 idle。
- 真实调用链：入口初始化 → 录音库 setView/setSearchText/load 发出通知 → 外录 Provider
  因监听依赖的可变状态而失效 → 销毁原控制器 → initialize 返回 superseded → 页面拒绝进入。
  单纯 keepAlive 只能保持无页面监听时的生命周期，不能阻止依赖通知触发重新创建。
- 三个问题订阅可追溯至 `4c1420ea1`（2026-07-26），用户指定的 `1176b5038` 中也存在。
  iOS VoiceRecorderBridge 与 `1176b5038` 相比无差异，因此不是删减把外录驱动删除。
- SQLite 中另有 `SCREEN_CAPTURE_APP_GROUP_UNAVAILABLE`，它属于内录能力检查，
  不是此次外录入口失败的原因。本轮不修改内录签名/权限，也没有查询或修改服务器。

### 修复与验证

- 外录 Provider 对录音库、录音卡、上传控制器改为订阅 `.notifier` 身份；这些实例的
  普通状态/进度通知仍由原来的监听机制处理，不得销毁正在初始化或录音的外录会话。
- 账户变化或依赖实例真正更换时仍重建控制器，并正常关闭旧账户的活动采集；不强制
  复活旧状态，不绕过 superseded 校验，也不整体回退原生实现或其他功能。
- 新测试使用生产 Provider 和真实的三个 ChangeNotifier，只替换账户、原生和网络边界，
  不再通过覆盖外录 Provider 工厂而掩盖依赖重建。修复前精确复现 superseded，修复后
  验证入口、活动录音、库/录音卡/上传通知及账户切换，连同既有外录测试共 23 项通过。
- 修改的 Dart 文件定向分析无 error/warning，保留既有 10 条 info 级风格提示。
  全工程 SCM 检查发现另一个已有录音卡 golden 图片改动缺少对应 SCM 更新；本轮没有
  修改该图片或其映射，本次两个源码/测试修改均先更新各自 SCM，未新增有效源文件。
- 真机调试同步时，旧运行包与当前根组件接口不兼容，且初次附加没有继承原 API 启动参数；
  已从原 `Generated.xcconfig` 恢复相同的 `HUAHUO_API_BASE_URL` 启动参数。确认外录与
  录音卡均为空闲、内录 unsupported、无活动文件传输后，完整重启 Dart 界面使版本一致，
  会话恢复返回 `/v3`；没有卸载 App、清空账号数据或修改无关源码。
- 通过正常应用路由重新打开真机外录入口后，实际页面 `_entryReady=true`、
  `_entryUnavailableMessage=null`，实际控制器 `_initialized=true`、status=idle、
  checkpoint=null；真机加载源码中的三处 notifier 身份订阅均已核实存在。
  使用 `d` 分离后确认物理 Runner 进程 54443 继续运行。
- 本轮没有自动启动麦克风或上传录音。真机验证证明此次入口失效已恢复，不等同于完成
  新一轮录音时长、锁屏后台采集及云端转写端到端验收。

## 范围与历史对照

本次仅调整 Flutter 的两类录音生命周期、入口行为和对应定向测试，不改聊天、文档导入、
录音卡传输、后端接口、转写模型或录音库数据格式。

已对照 `1176b5038db27cbb029224c84760e3afbacdd0b5`。该版本的麦克风通道与当前版本
一致，已有 iOS 后台音频配置及 Android 麦克风前台服务继续保留。进一步追溯到旧入口
未使用离开结束守卫的实现，恢复“离开页面仍录音”的语义，而不是整体回退历史文件，
避免丢失后来加入的账户归属、持久化恢复与共享上传流程。
