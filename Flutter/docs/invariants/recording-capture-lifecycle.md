# 外录与内录生命周期约束

外录 Provider 按录音库、录音卡和上传控制器的实例身份建立依赖。
普通状态或进度通知不得销毁活动录音会话；账号或依赖实例真正变化时，
仍须释放旧会话并拒绝旧回执。保活不能替代依赖身份校验。

## 外录：麦克风录音

| 阶段 | 状态及所有者 | 退出条件 |
| --- | --- | --- |
| 准备 | 查询/请求麦克风权限，启动原生录音 | 原生启动成功后进入 recording；拒绝则显示错误 |
| 采集 | 账户级保活控制器持有 recording/paused 会话 | 用户显式停止或取消，或原生终止 |
| 停止 | 在第一个异步等待前进入 stopping，失效旧查询与控制回执 | 原生返回真实音频文件 |
| 交接 | 保存本地录音并交给既有共享上传/转写任务 | 持久化任务接管后显示其进度 |

- 返回上一页、切换到其他功能不会调用停止/取消；再次进入外录页接回同一个会话。
- 暂停/继续不接受旧录音状态回执；快照查询由独立请求标识持有，避免暂停使刷新永久锁住，
  也避免旧查询释放新查询的占用标识。
- 保留退出账户/控制器销毁时的资源释放语义；后台能力不等于承诺系统杀进程后继续录音。
- 外录是麦克风采集，不是系统声音录屏，不通过内录通道实现。

## 内录：录屏、提音频、云端转写

| 阶段 | 前置条件与完成证据 | 失败与恢复 |
| --- | --- | --- |
| 能力检查 | 已登录、账户本地库可用、原生平台支持 | 不支持时解释原因，可导入已有录屏视频，不自动换成麦克风 |
| 等待授权 | 先持久化本账户 sessionId，再打开原生系统同意入口 | 取消不创建转写任务；未确认开始前不显示正在录制 |
| 正在录屏 | 匹配会话的原生 recording 回执 | 页面离开不停止；前台恢复时按原生会话对账 |
| 停止并保存 | 先保存停止意图，调用原生停止 | 停止确认仅代表命令受理，继续等最终媒体；错误保留停止入口 |
| 视频可用 | 原生完成私有 MP4 并提供会话、URI、时长等媒体凭据 | 忽略其他会话回执；完整媒体写入检查点后才继续 |
| 分离音频 | 已有最终视频；提取并验证 M4A 类型和有效时长 | 保留 MP4 重试；不得上传无音轨、过短音频或原始 MP4 |
| 本地归档 | 记录 registeringLocal，再把派生音频复制到账户录音库 | 已有本地录音复用，不重新录制 |
| 上传交接 | 稳定本地 ID/jobId 与 handingOff 检查点，复用共享上传控制器 | 同一任务恢复，保持既有鉴权、工作区、raw_material 与幂等约束 |
| 清理完成 | 上传任务已接管且 handedOff 刷盘，释放中间 MP4/M4A 后保存 completed | 释放失败或异常仅重试清理，不重复提取/上传，不删除录音库正式副本 |

系统录屏文件通过现有原生会话日志/事件取得并保存在应用私有目录，不依赖扫描相册猜测
“最后一个视频”。已有视频导入继续使用系统文件选择器，用户选定后复制到私有空间，
然后进入同一条音频提取和上传流程。此次没有新增相册、全盘存储或后台录屏权限。

检查点追加 stage 字段，兼容无此字段的旧记录。写盘按不可变快照串行执行；恢复不是
单纯读取 stage 后跳转，而是核对原生会话、真实媒体、本地归档以及上传草稿。
命令、状态查询和媒体处理有各自的归属与单飞边界，迟到回执不能覆盖新阶段。

`InternalRecordingStatus.completed` 只表示音频准备、共享任务交接及中间文件清理
完成，不代表云端 ASR 已完成。上传凭证、对象上传、完成确认、创建录音、ASR 排队/
成功/失败继续由原有上传草稿和转写详情状态机负责，不提前显示转写成功。

历史修复与验证边界见[原审查记录](../../reports/recording/recording-capture-lifecycle.md)。
