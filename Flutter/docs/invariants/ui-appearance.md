# UI 外观一致性约束

## 判定规则

同一个组件在同一主题、同一显式业务状态下，只有一套几何、底色、边框、
文字和图标规则。主题选择、选中、聚焦、禁用、错误、处理中仍是必要且明确的
输入；不能为了“唯一”冻结正常交互。

启动时着色器是否就绪、性能档位、是否位于滚动容器、页面所属的 home scope、
图谱在组件背后如何移动，不再替同一个控件选择另一套外观。先消除重复的
绘制/主题所有者，再检查状态映射，不通过增加一个覆盖层掩盖原来的实现。

## 后续维护约束

- 新增组件先复用对应公共组件；若确需独立视觉身份，显式传入 variant/tokens。
- 不在同一 surface 外再增加一层独立底色或阴影来修正颜色。
- 不在渲染函数里用设备性能、生命周期或祖先滚动条件决定颜色/圆角。
- 固定功能主题使用 fromTokens，不只替换 ColorScheme 而保留外层扩展。
- 不把历史报告的有限回归结论扩大成“所有页面、所有设备均已逐像素验证”。

历史修复与验证边界见[原审查记录](../../reports/ui/ui-appearance-consistency-audit.md)。
