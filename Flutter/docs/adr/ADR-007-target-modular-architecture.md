# ADR-007：交接期目标架构

- 状态：Proposed；重构方向已获授权，以下为后续实现的设计基准建议，不代表迁移已经完成。
- 日期：2026-10-02
- 适用范围：Flutter 移动端、桌面端与共享包。后端部署架构不在本次范围。

## 背景

项目处于停滞交接期，允许重新划定模块和依赖，不以兼容旧目录为目标。
现有客户端包含聊天、编辑、支付、后台任务、离线存储及录音设备协议，
仅统一 HTTP 调用不足以支撑后续迭代。保留已验证的协议语义与数据恢复
机制，不要求保留现有类、目录、provider 或大文件。

本建议延续 ADR-003 的状态所有权、ADR-005 的长任务规则及 ADR-006 的
移动/桌面独立入口和按真实消费者提取共享代码规则，不废止这些约束。

## 目标：按业务能力组织的模块化单体

每个应用仍独立构建和发布，业务模块拥有自己的状态、数据访问接口、
流程及界面。复杂模块采用端口与适配器结构；简单查询只需要一个清晰的
Repository 查询入口，不按 URL 数量创建 Repository、UseCase 或 DTO 副本。

项目业务请求统一采用 `Page → Controller → Repository → API Client →
底层封装`。Repository 接口属于业务模块，远程实现负责 DTO 映射和数据
来源组合；Controller 通过构造参数接收接口，不导入具体远程实现。

依赖规则：

```text
应用装配 → 页面/应用服务 + 外部适配器（负责连接两者）
页面 → 本模块应用接口、视图状态
应用服务/状态机 → 业务模型、能力端口
远程/本地/原生适配器 → 能力端口 + 对应基础设施
基础设施 → 平台/网络/数据库 SDK
```

数据运行时可以从应用服务流向适配器，但应用规则不导入适配器的具体
实现。领域模型不依赖 Flutter、Riverpod、HTTP、数据库或平台插件。
Riverpod 保留为装配、界面订阅和生命周期工具，不成为业务规则的入口。
组合根创建依赖，业务对象通过构造参数接收依赖；业务逻辑不使用全局
容器或服务定位器。界面使用本模块的绑定，不反向导入全应用 bootstrap。

跨模块调用只通过公开应用接口；禁止导入另一模块的 data、presentation
或私有实现。需要返回值和失败语义的操作使用显式调用。事件只用于确有
需要的独立通知，不建立承载全部业务的全局事件总线。跨模块流程由一个
明确的应用协调器负责，不能用多个页面各自发请求来拼接流程。

## 网络边界

共享 API 能力包含两个职责，可先在一个包内以模块边界实现：

1. 网络运行机制：可替换 Transport、公共元数据、超时/取消、错误映射、
   trace、认证策略接入、请求去重和受约束的重试。
2. 按业务域组织的协议客户端：端点定义、请求/响应 wire DTO、解析与
   协议校验。认证、支付、聊天、录音等有各自公开入口，不再汇入巨型
   domain_clients 或 contract_models 文件。

业务应用层通过 Repository 能力接口访问数据；简单远程查询也保持这条
边界。Repository 可以组合 API、数据库和缓存，复杂命令由 Controller
或其委托的应用服务/状态机编排。
接口按能力设计，而非按 URL 数量制造抽象层。API Result/wire DTO 不直接
成为页面状态；只有业务语义不同时才增加映射类型。

多个服务使用显式 Service 配置：地址、认证对象、Token 受众、超时和
允许的重放方式。统一的是机制，不是跨服务共享 Token 的假设。刷新失败、
登出、账户或工作空间切换必须定义请求取消和迟到结果丢弃规则。认证刷新
须防止并发重复刷新；命令只有协议支持幂等且保留同一操作标识时才可重放。

文件上传下载、SSE、语音网关是明确的专用适配器，不绕到 feature 内部
随意创建网络客户端。签名资源地址不默认携带主服务认证头；大文件走流式
传输与独立资源预算。统一诊断记录脱敏的操作、耗时、结果和 trace，不记录
Token、签名 URL、录音内容或原始敏感请求体。

现有网络机制可以成为实现材料。替换为 Dio 或引入代码生成必须解决明确
缺口，不作为目标架构的先决条件。只有获得并验证权威、版本化的协议定义
后才生成 wire DTO/client；生成物不承载业务规则，也不手改。当前静态契约
检查继续只证明定义一致性，不宣称服务端联调通过。

## 数据、任务与设备边界

每类持久化数据只有一个写入权威与明确事务边界；本地读模型、可丢弃缓存、
用户文档和不可丢失的操作记录分别声明语义。目标是统一存储生命周期、
账户隔离及迁移责任，不是立即让所有文件和缓存使用同一种存储介质。
旧 schema 与恢复路径在明确支持范围和迁移验证前不得删除。

调度器负责执行资源和取消；业务状态机负责状态转移；Repository/ledger
负责持久化；页面和通知观察状态。这些职责可以合作，不能合成万能任务类。
接受请求、后台接管、处理完成和结果可读取仍是不同状态。

原生通道/设备协议封装在平台适配器；连接会话、传输过程、业务账本各有
单一所有者。连接 epoch、乱序回调过滤、断点续传不得因移动代码而丢失。
真机相关验收必须来自真机，离线协议测试只能证明模拟输入下的行为。

## 共享代码与工程组织

移动端和桌面端只共享相同语义的业务规则与协议能力，不强求共享页面、
导航或平台生命周期。共享业务层保持纯 Dart；远程适配器不能反向污染
业务接口。优先明确模块边界，再按实际消费者决定是否拆物理 package。

现有 huahuo_product 可作为共享业务重组的起点，domain/application 与
remote adapters 必须有独立公开边界。huahuo_foundation 是 Flutter 视觉
包，不作为所有业务层都依赖的底层。编辑器仍是专门能力。没有真实共享
消费者的能力留在其应用内，不创建空的通用框架包。

目标应用入口可以命名为 apps/mobile 与 apps/desktop；顶层路径迁移是
单独机械批次，必须覆盖构建、资源、原生工程和工具引用。目录改名不能
作为业务模块重构完成的证据。UI 版本号不作为业务模块名称。

## 验收及代价

新增代码由 import graph/AST 边界规则约束，不只依赖文件行数或文字约定。
每个垂直迁移切片包含应用测试、适配器协议测试及相关界面回归。离线测试、
外部服务测试、模拟器和真机验证分开执行和报告。迁移期旧例外有明确范围
及退出任务，禁止用扩大预算消除失败。

代价是迁移期需要短期兼容入口和更明确的接口设计。每个新入口替代旧入口
后应删除重复路径；不能长期维护两套功能代码。先用一个真实能力验证模板，
再复制结构；禁止先铺设大量空 package、逐接口空转发层或自研通用框架。

这是一份新结构的目标约束，不证明当前代码符合它，也不授权改变后端协议、
执行服务器写操作或丢弃用户数据。
