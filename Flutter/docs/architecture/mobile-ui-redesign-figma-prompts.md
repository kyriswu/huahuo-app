# Figma 分批生成提示词

这些提示词配合 [移动端 UI 重设计说明](mobile-ui-redesign-figma-brief.md) 使用。每次生成前先选中对应 Page，继承 `01_Foundations` 与 `02_Components` 的变量和组件。画布以移动端 390×844 为主，关键页另做 360×800 和 430×932。不要在一次生成中跨越所有模块。

所有提示词都遵循同一组硬约束：中文移动端产品；暖白、安静、内容优先；真实状态优先于装饰；采用 Auto Layout；文字与按钮可读；不生成代表作或其改名替代物；知识图谱保留真实可操作的 3D 球面视觉；没有数据时不编造用户内容；未接入能力画说明或禁用状态，不画伪成功。

## 0. 基础系统

```text
建立花火移动端 UI 基础系统。产品是个人知识沉淀与创作工具，默认浅色：暖白画布、白色表面、深灰文字、琥珀色主动作，少量青绿/紫灰/蓝灰用于知识类别。建立 canvas、surface、surface-secondary、text-primary、text-secondary、border、accent、accent-soft、success、warning、danger，以及图谱深色 canvas/text 变量。字体使用中文无衬线，标题 28/34、页面标题 22/28、分区 18/26、正文 16/24、次要 14/20、标签 12/16；基础间距 4/8/12/16/24/32，左右边距 20，卡片圆角 16，大面板 24，按钮高 48，点击热区至少 44×44。

建立组件：TopBar、BottomNavigation、SegmentedControl、Button、IconButton、TextField、SearchField、FilterChip、SourceBadge、StatusBadge、NoteCard、FileRow、TaskProgressCard、MessageRow、AttachmentCard、AudioPlayer、RecordingControls、GraphNodeLabel、GraphNodeCard、GraphToolbar、DiffBlock、EmptyState、InlineError、Skeleton、Toast、BottomSheet、ConfirmDialog、PermissionExplanation。为按钮、输入框、任务、文件、录音建立 Default/Pressed/Disabled/Loading、Focused/Error、Waiting/Running/Verifying/Succeeded/Failed/Partial、Local/OnDevice/Transferring/Missing、Ready/Recording/Paused/Finishing/Failed variants。玻璃效果只用于图谱浮动工具和必要底栏，阅读正文与编辑器使用实色背景。
```

## 1. 知识图谱（最先生成）

```text
生成 B01「知识图谱」移动端首页，390×844。顶栏包含个人入口、「知识图谱」标题、搜索和消息；下一行是「3D 图谱 / 笔记列表」分段开关。页面主要面积是可操作的 3D 球面知识图谱：有前后深度、柔和节点、不同类别色、真实关系细线和少量焦点标签，体现一个人的观点、方法、灵感、案例与行业正在形成关系网络。球体必须像产品核心舞台，不能缩成卡片，不能换成普通 2D 列表，也不能只是背景插画。底部有记录主按钮、聊一聊快捷操作和四项导航「知识图谱 / 创作空间 / 资产 / 我的」。

请创建以下 Frame：Default-Light、Default-Dark、Node-Selected、Empty、Loading、Stale-Error、Dense、Reduced-Motion，以及 List-Default。选中节点时从底部出现 GraphNodeCard：类型、标题、两行摘要、来源/时间、「查看内容」主按钮、「聊一聊」次按钮；球体保持可见。实体节点没有本地笔记时不要显示编辑按钮。空状态只显示引导记录，不虚构个人知识。用注释说明单指拖动旋转、双指缩放、点击选中、长按/拖动节点、空白清除、进入全屏和重置视角。装饰连线与真实语义边视觉上区分。
```

## 2. 全屏图谱与搜索

```text
生成 B02「全屏 3D 图谱」与 B03「节点详情」两个移动端设计。全屏画布保留返回按钮，减少永久工具，仅在必要时显示图谱工具和节点卡；选中内容可进入内容详情或对话。为 B03 分别生成本地笔记节点卡和远端实体详情：远端实体显示名称、真实类型、摘要、属性、关系和可用来源，数据不支持的字段不显示。再生成 B04 搜索结果、无结果和筛选状态，搜索当前图谱与全库资产范围要用清楚的范围选择，不把二者混在一起。
```

## 3. 记录、导入与转写

```text
生成 C01—C14 的采集与转写流程，优先做 C01 记录入口、C02 独白、C04 写笔记、C06 文档导入、C09 外录、C11 转写任务、C12 转写详情。入口菜单按独白、文字、链接、文件、音频、外录、内录分组；不要重复展示相同的导入卡。录音页面突出计时、波形、麦克风状态、暂停/继续、完成；波形表示正在录音，不表示转写成功。导入和转写使用统一任务卡，明确上传、排队、处理中、待核验、完成、失败、部分成功。离开页面后任务仍可从消息中心找回，只有真实支持后台继续时才显示这句话。补充权限拒绝、无文件、格式错误、解析失败、系统录屏交接、连接丢失和未保存退出状态。
```

## 4. 内容与对话

```text
生成 D01 内容详情、D02 聊一聊、D04 聚合材料选择、D05 聚合任务结果。内容详情以正文为主，支持原文/纲要/深度洞察层级，显示来源、标签、时间、关联材料；AI 操作收进清晰的操作区，不压过文章。对话页包含上下文引用卡、消息流、附件预览条、文本/语音输入；长回答可读，运行过程可按需展开，断线保留已输入和已返回内容。聚合页显示所选材料、目标、真实任务阶段和结果，展示失败与恢复。不要新增没有数据依据的社交动态或公开社区。
```

## 5. 创作空间

```text
生成 E01—E09 创作空间。E01 首屏包含继续上次草稿（有才显示）、自由创作主按钮、选题推荐、个人 IP、获客营销、视觉设计、视频分析工具；不要出现代表作或其替代名称。E03 是材料选择，E04 是生成中，E05 是结果，E06 是自由创作编辑器，E07 是 AI 改写审核，E08 是创作历史，E09 是选题任务详情。编辑器大面积给正文，顶部显示返回、标题、保存状态，底部提供 AI 改写；审核态用红色删除线和绿色新增底纹并配文字标签，底部固定接受/放弃。视频分析使用对话式场景，不要再画一套旧的独立三页。
```

## 6. 资产、外部世界与阅读

```text
生成 F01 资产中心、F02 文件夹/标签、F03 影像预览、F06 录音文件、F07 外部世界、F08 栏目详情、F09 文章阅读、F10 订阅管理。资产中心用已沉淀/影像分段、文件夹路径、搜索、筛选、排序和内容列表；搜索入口与 B04 复用组件但要显示当前范围。外部文章与个人笔记用来源徽标区分，外部文章先阅读或创建副本，不直接覆盖原文。卡内录音、本地录音、云端转写分成清楚的状态层。空、同步失败、无结果、部分批量失败都要有可操作出口。
```

## 7. 数字孪生、定位与设备

```text
生成 G01 社媒定位报告、G02 数字孪生、G04 候选审核、G06 正式版本，以及 H02 录音卡控制、H03 设备管理、H05 卡内文件、H06 Wi-Fi/蓝牙传输。数字孪生页用抽象粒子人表达个人认知积累，和知识图谱的关系网络视觉区分；文件视图显示材料、待审差分、正式版本。候选必须经过差分、讨论、确认与核验才能进入正式版本，不能直接画成功。设备页明确卡内/本地/上传/转写四种阶段；低电量、断连、权限拒绝、热点交接、部分失败都要画。系统权限交接使用说明页，不伪造系统 UI。
```

## 8. 登录、我的与设置

```text
生成 A01—A06、I01—I16 的登录、首次设置、个人、会员、声纹、日历、帮助和设置页面。登录采用手机号/验证码与协议；首次设置按声纹、录音卡、设备归属分步并允许稍后完成。我的首页只保留资料、会员、数字孪生、外部世界、资产、录音文件、设备、设置等真实目的地，不出现代表作和花火商学院占位入口。会员页画实际套餐、协议、支付等待确认、恢复购买和交易记录状态；设置页分为账号安全、外观、权限隐私、提醒、帮助反馈、版本、关于和诊断。注销服务尚未接入、日报只保存本机偏好时，画清楚限制说明，不画完成态。
```

## 9. 原型连接与 QA

```text
把以下原型串起来并在 11_Prototype-QA 建立检查画板：登录→首次设置→知识图谱；图谱节点→内容详情→聊一聊→自由创作→资产；记录→转写→消息→结果；外部文章→沉淀→资产；录音卡→传输→本地录音→批量转写；数字孪生材料→候选差分→审核→正式版本；会员购买→等待确认→权益。每条主链路补一个失败/重试和离开后恢复分支。检查 360 宽、键盘避让、长标题、长文、大字、深色图谱、减少动态效果、底部安全区、44×44 点击热区、对比度和代表作不出现。Smart Animate 只模拟过渡；用注释说明真实 3D 旋转/缩放必须由运行时实现，静态 Figma 不是 3D 完成证明。
```

## 10. 设计生成后的人工复核问题

- 首屏是否在 3 秒内看出 3D 知识图谱是产品卖点？
- 旋转、缩放、选择、返回是否有明确视觉和按钮路径？
- 用户能否从图谱节点直接到内容、对话和创作，又能返回原视角？
- 代表作是否彻底从页面、导航、组件和示例文案消失？
- 处理中、失败、待核验、部分成功是否真实且可恢复？
- 卡内文件、本地文件、云端任务、正式资产是否被准确区分？
- 图谱装饰线是否被误读为真实语义关系？
- 长文、键盘、大字、深色图谱和减少动态效果下是否仍可用？
