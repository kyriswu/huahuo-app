# 花火移动端 UI 重设计说明 · Figma 设计输入

版本：2026-10-04 · v1.0 · 性质：设计提案，未实施的新版 UI。

## 0. 阅读与使用方式

这份文档把现有移动端产品能力转成新版页面设计要求。适用于设计师、Figma AI / Figma Make 及后续开发评审。建议先读第 1—4 节确定方向，再按第 5 节逐组生成页面，最后用第 10 节验收。可直接复制的提示词见 [Figma 分批生成提示词](mobile-ui-redesign-figma-prompts.md)。

**两条已确认的硬要求：新版方案彻底移除「代表作」页面与相关入口；知识图谱的 3D 效果必须保留，并成为产品的核心视觉卖点。** 用户已确认只修改设计方案，现有代表作代码、内容及数据不在本次删除范围。

本次覆盖 `Flutter/src` 移动端：启动与登录、定位与引导、知识图谱、记录与导入、AI 对话、内容详情、聚合、创作、资产、外部知识、数字孪生、录音卡、会员及个人设置，以及关键弹窗、抽屉和系统交接状态。桌面应用按当前仓库范围冻结，不制作桌面新版页面。

“现有”表示阅读当前源码可确认存在对应入口或表现，不表示已在真机或线上验证。“新版”表示本次建议的视觉、命名和导航调整。未接入能力单列说明，不生成虚假的可用状态。

## 1. 产品定位与设计目标

### 1.1 一句话定位

**把每天的声音、阅读和想法，沉淀成看得见关联、用得起来的个人知识，再协助用户持续创作。**

产品主线：记录 / 导入 → 整理成笔记 → 在知识图谱中发现关联 → 与 AI 讨论 → 形成内容 → 保存为个人资产。数字孪生帮助积累用户的表达方式、观点和方法；录音卡降低真实场景的采集成本。

核心受众沿用当前产品能力：持续输出内容的个人创作者、经营个人 IP 或业务的专业人士，以及通过会议、课程、阅读积累素材的知识工作者。设计不额外扩展团队协作、公开社区、课程交易或作品售卖。

### 1.2 本轮要解决的问题

| 当前观察 | 新版设计决策 | 用户得到的收益 |
| --- | --- | --- |
| 主壳有思想图谱、工作台、代表作三个模式，另有个人侧栏 | 删除代表作；建立四个带文字的稳定主入口 | 不再靠隐藏手势和页码点理解产品 |
| 图谱和列表是同一知识集合的两种浏览方式 | 统一命名为「知识图谱」，保留「3D 图谱 / 笔记列表」切换 | 第一眼有记忆点，日常查询仍高效 |
| 搜索、资产、个人功能存在多个重叠入口 | 一个资产中心承接整理与搜索，允许多个入口到达同一页面 | 少学一套概念，少维护一套 UI |
| 录音、文件、转写、AI 生成均有异步过程 | 统一进度卡、消息入口、可恢复状态 | 清楚任务在哪一步，离开也找得回来 |
| 数字孪生既有展示，也有材料、差分和版本操作 | 展示页突出价值，文件及修订分层展开 | 看得懂“它学到了什么”，保留审核控制 |
| 多处存在占位或未接入能力 | 主流程只展示真实能力；占位收敛到说明 | 避免点击后进入伪成功流程 |

### 1.3 保留与移除边界

- 必须保留：3D 球面知识图谱、笔记列表、采集与导入、录音卡、转写、AI 对话、自由创作、个人 IP / 获客营销创作、视觉设计和视频分析入口、资产与订阅、社媒定位、数字孪生、账号与会员。
- 从新版移除：代表作首页、代表作分页 / Tab、书籍封面式代表作入口、章节目录、新建章节、代表作信息、代表作 AI 写作、代表作专属版本比较与生成面板。
- 不把代表作改名为“长篇作品”“个人著作”后重新塞回导航。通用自由创作、创作历史仍保留，因为它们独立存在。
- 下线入口不等于删除用户历史内容。历史代表作的数据迁移、归档或访问政策属于未来实施决策，本方案不承诺自动变成笔记，也不删除数据。

## 2. 新版信息架构与导航

### 2.1 四个主入口（设计提案）

| 主入口 | 首屏内容 | 二级目的地 | 明确边界 |
| --- | --- | --- | --- |
| 知识图谱 | 3D 知识球体；可切笔记列表 | 节点详情、内容详情、聚合、聊一聊、采集 | 面向“发现与思考” |
| 创作空间 | 继续创作、自由创作、选题与工具 | 编辑器、材料选择、生成过程与结果、定位报告 | 面向“生成与编辑” |
| 资产 | 已沉淀、影像；文件夹与检索 | 内容详情、录音文件、资产概览、外部世界 | 面向“查找与整理” |
| 我的 | 资料、会员、数字孪生、设备与设置 | 录音卡管理、声纹、日历、帮助、安全与隐私 | 面向“管理个人与设备” |

资产页与图谱列表显示同一批个人内容，但承担不同任务：图谱列表强调最近记录、内容浏览和关联；资产页强调文件夹、来源、筛选和批量管理。不得制作两套看起来互不相通的知识库。

主入口使用图标 + 中文文字，选中项清晰可见。建议底栏 4 项，不把「+」算作第五个 Tab。知识图谱页提供醒目的「记录」按钮与「聊一聊」快捷操作；其他页按任务展示主按钮，避免全屏常驻多个抢眼悬浮按钮。

### 2.2 全局入口与返回规则

- 顶栏搜索 → 资产搜索模式；从图谱发起时可携带搜索词。图谱内“定位节点”只搜索当前图谱，不能把它伪装成全库搜索。
- 顶栏消息 → 消息中心，承接任务完成、失败、待处理及业务通知。仅呈现现有数据支持的消息，不额外设计一个无数据源的全局任务平台。
- 首页记录菜单 → 独白、写笔记、粘贴链接、导入文件、导入音频、外录、内录。录音卡从设备入口进入，也可在录音来源选择中到达。
- 一级页显示底栏；编辑器、录音、阅读详情和全屏图谱进入专注模式，保留清晰返回。切 Tab 不等于取消任务。
- 返回内容列表保留筛选与滚动位置；从节点返回图谱保留选中上下文和视角，这是新版交互目标。
- 仍在录音或任务运行时，离开确认必须说明实际后果。只有确实支持后台继续的操作才使用“可离开，完成后通知你”。

### 2.3 统一名词

| 当前词汇 | 新版对用户展示 | 说明 |
| --- | --- | --- |
| 思想图谱 / 知识图谱 | 知识图谱 | 统一产品名词 |
| 1D | 笔记列表 | 不要求用户理解维度术语 |
| 3D | 3D 图谱 | 明确保留品牌卖点 |
| 工作台 / 创作空间 | 创作空间 | 一个导航名称 |
| 独白 | 独白 · 语音记想法 | 保留特色词，同时解释用途 |
| 外录 | 外录 · 会议 / 谈话 | 手机麦克风采集环境声音 |
| 内录 | 内录 · 设备声音 | 当前独立页通过系统录屏获取声音；平台差异按实际能力展示 |
| 蒸馏到数字孪生 | 让数字孪生学习 | 解释为学习观点、方法与故事；仍需要候选审核 |

## 3. 视觉方向：温润内容界面 + 有空间感的知识星球

### 3.1 整体气质

日常界面采用暖白底色、清晰排版、柔和边界和少量琥珀色强调。阅读、编辑与管理页面保持安静；3D 图谱与数字孪生承担产品的视觉记忆点。避免所有页面都铺满玻璃卡片、渐变和发光边框。

主方案以浅色为默认。3D 图谱同时提供一张深色演示稿，用于比较空间层次和演示效果；它是图谱页的主题变体，不强制全应用变成科幻暗黑风。首轮设计就交付浅色与深色图谱，其他页面先完成浅色，组件预留深色变量。

### 3.2 建议设计变量（新提案，非当前代码值）

| Token | 浅色建议 | 使用位置 |
| --- | --- | --- |
| canvas | #F7F6F2 | 页面背景 |
| surface | #FFFFFF | 卡片、输入区、浮层 |
| surface-secondary | #EEECE6 | 弱分区与禁用容器 |
| text-primary | #202622 | 标题与正文 |
| text-secondary | #626B65 | 次要信息 |
| border | #DFE3DC | 分割与描边 |
| accent | #9A531C | 主要动作、品牌强调 |
| accent-soft | #FAEBD9 | 选中容器、提示背景 |
| success | #28714F | 完成状态 |
| warning | #8E650B | 待确认、处理中异常 |
| danger | #B63C3C | 删除、失败 |
| graph-dark-canvas | #101916 | 深色图谱空间 |
| graph-dark-text | #EEF3ED | 深色画布标签 |

图谱类别色建议：观点与趋势用琥珀，方法用青绿，灵感用紫灰，案例与行业用蓝灰。颜色只表示当前数据可支持的分类；人物、组织、项目等真实实体类型保留原标签，不能强行改写为六类业务素材。分类色搭配图标和文本，不能只靠颜色区分。

字体使用 Figma 环境可用的中文无衬线字体，优先 Noto Sans SC / 思源黑体，英文和数字使用 Inter。标题 28/34、页面标题 22/28、分区标题 18/26、正文 16/24、次要信息 14/20、标签 12/16。金额、时长、录音计时使用稳定的数字宽度。

基础间距 4/8/12/16/24/32；左右边距 20；卡片圆角 16；大面板 24；按钮高 48；可点击区域至少 44×44。小型可视图标允许小于 44，但点击热区不能缩小。重要正文与按钮文字对比度达到 4.5:1，交互轮廓与必要图形达到 3:1。

### 3.3 版式和材质

- 主画板 390×844，关键页面另做 360×800 和 430×932，单位均为逻辑像素。安全区独立成层，按目标设备替换，不烘焙进内容尺寸。
- Figma 使用 Auto Layout；标题支持两行，长文件名可换行或中间省略，底部按钮始终不被键盘遮挡。
- 玻璃材质仅用于图谱上的浮动工具、轻量节点卡与必要底栏。阅读正文和编辑输入区使用实色背景。
- 相同组件在相同主题和状态下保持同一外观；加载、失焦、滚动和设备性能不另造一套颜色与圆角。
- 图标统一一种线性风格，选中状态通过底色和文字强调。禁止用表情符号代替正式功能图标。

## 4. 3D 知识图谱专项设计（P0，必须完整交付）

### 4.1 保留什么

当前源码与测试资产可确认：已有球面布局、投影、自动与手动旋转、缩放、节点选择和拖动、节点详情 / 本地笔记操作卡、全屏模式、图谱状态提示，以及前后台与减少动态效果的控制。现有视觉参考是浅色球形网络；新版允许调整视觉强度，但不能将它替换成普通列表、平面关系树或一张不可操作的球体图片。

**新版主张：让用户一眼看到“自己的知识正在形成一个有空间、有关联的整体”，点下去又能立即读内容、讨论或创作。**

### 4.2 首页构图

从上到下：安全区 →「知识图谱」标题、搜索、消息 →「3D 图谱 / 笔记列表」分段开关 → 数据状态 / 简短提示 → 主要 3D 舞台 → 快捷操作 → 底部导航。

在 390 宽画板上，3D 舞台建议高 420—500，球体直径约 300—330；根据安全区和字体动态调整。图谱必须占据首屏主要面积，不能缩成顶部的小卡片。未选中时尽量减少覆盖；选中时从底部出现节点卡，球体保持可见。

空间层次由前后深度、节点尺寸、明暗与细线透明度共同构成。前景节点清晰，背部节点减弱，选中节点及其真实关系突出。不要把所有标签同时展开；默认只显示少量关键节点与当前焦点标签。设计样例可以使用约 40 个可见点和 6—10 个标签演示层次，这只是视觉样例，不是运行时数据上限。

现有球面网格 / 装饰线与真实语义关系必须在视觉上区分。装饰线更细、更弱、无关系文案；被选中的真实边才展示对应关系标签。不要把“为了成球而连接的线”表现为 AI 已确认的知识关系。

### 4.3 手势与反馈

| 用户动作 | 设计反馈 | 约束 |
| --- | --- | --- |
| 首次进入 | 短暂、缓慢地展示球体转动，再稳定 | 不持续自转干扰阅读；减少动态效果时直接静态出现 |
| 在空白舞台单指拖动 | 旋转球体，节点按前后深度更新 | 不同时触发主 Tab 翻页 |
| 双指捏合 | 缩放，保留可找回全图的操作 | 工具必须可点击，不能只依赖手势 |
| 点击节点 | 暂停自动运动、选中高亮、打开摘要卡 | 手指移动超过阈值时不能误触打开详情 |
| 长按 / 拖动节点 | 表现节点被抓取、移动后的稳定位置 | 与“旋转整球”明确区分；精确阈值由实现确定 |
| 点击空白 | 收起节点卡、清除选择 | 不能重置用户全部浏览状态 |
| 打开节点卡详情 | 进入内容阅读或实体详情 | 实体未绑定本地笔记时不显示不可用的笔记编辑动作 |
| 点击全屏 | 进入沉浸图谱，显式返回按钮保留 | 全屏不需要永久摆放一整排工具 |
| 图谱被浮层遮挡 / App 后台 | 视觉运动暂停 | 不改变同状态组件的颜色与外观 |

“重置视角”建议放在首页图谱工具中；全屏通过「更多」提供。新增工具布局属于本方案交互提案，后续实现需保持现有手势和生命周期约束。

### 4.4 节点卡信息层级

本地内容节点：类型 + 标题 → 两行摘要 → 来源 / 时间 →「查看内容」主按钮与「聊一聊」次按钮；创作入口放在内容详情中，避免一张小卡塞四个主操作。

实体节点：实体名称 + 原始类型 → 简述 / 已知属性 → 关联关系与可用来源。没有摘要写“暂无摘要”，没有本地内容不展示编辑按钮。若关系方向或类别由数据提供，保留其含义；未知关系不能设计成确切因果。

### 4.5 必画的 10 个图谱状态

1. `B01/3D/Default-Light`：浅色、正常数据、无选择。
2. `B01/3D/Default-Dark`：深色视觉变体，同一批数据。
3. `B01/3D/Node-Selected`：选中真实笔记，显示操作卡。
4. `B03/Entity-Selected`：无本地笔记的实体详情与关系。
5. `B02/Fullscreen`：大画布、少控件、清晰返回。
6. `B01/3D/Empty`：空球壳 / 引导线 +「记录第一个想法」，不能虚构个人知识。
7. `B01/3D/Loading`：轻量骨架 / 当前数据保留 + 同步提示。
8. `B01/3D/Stale-Error`：已有内容仍可浏览，提示更新失败并重试。
9. `B01/3D/Dense`：密集数据时保持标签可读，优先突出焦点与邻居。
10. `B01/3D/Reduced-Motion`：稳定空间布局，无自动旋转，仍可手动操作。

另需 `B01/List/Default` 与 `B04/Search-Empty`，证明 3D 与效率操作可以共存。低性能状态应优先减少装饰、标签密度与运动，保留 3D 空间辨识；用户可主动切列表。不以“性能优化”为理由从产品方案删除 3D。

Figma Design 中用多个视角帧、节点选中帧和交互注释表达旋转 / 缩放意图，Smart Animate 只作近似演示。真实连续 3D 仍须运行时实现；静态 Figma 交付不能标注为真实 3D 已完成。

## 5. 完整页面与关键界面清单

这是人工整理的产品设计清单，按用户任务合并重复路由。ID 用于 Figma 命名，不等于代码文件或路由数量。「保留重设」表示保留现有能力、重做视觉；「合并」表示多个入口共用同一个设计；「限制」表示现阶段不能承诺完整服务。除标注移除 / 不生成的项目外，均纳入新版交付。

每项至少交付默认状态；表中所列异常 / 过程状态必须另画或作为可检查的组件 Variant，不能只写在备注里。

### A. 启动、登录与首次使用

| ID / 页面 | 去向 | 主要布局与动作 | 必需状态 |
| --- | --- | --- | --- |
| A01 启动与恢复 | 合并启动、工作区恢复 | 品牌标识 + 简短恢复提示；进入账号对应工作区 | 初始加载、会话恢复失败、工作区恢复失败、重试 / 重新登录 |
| A02 手机号登录 / 注册 | 保留重设 | 品牌短句、手机号、验证码、协议、登录；底部帮助与客服 | 未填、发送中、倒计时、验证码错误、登录中、登录失败 |

## 6. 核心页面的具体排版要求

### 6.1 B01 知识图谱与列表

主视觉执行第 4 节。列表模式保留相同顶栏和底栏，分段开关保持原位；内容卡按“来源标签 → 标题 → 摘要 → 时间 / 处理状态”组织。最近新增有轻提示，不用大面积高饱和色标记每一条。筛选与聚合在工具栏，批量选择时底部出现选择计数和单一下一步动作。

首页示例数据使用「表达为什么要有自己的证据」「一次客户访谈的三个发现」「把案例转成可复用方法」「如何设计一场深度访谈」等真实语气标题。样例账号和内容均为虚构，不从私人录音提取原文。示例数据标记放在设计注释区，不放进正式产品文案。

### 6.2 E01 创作空间首页

顶栏“创作空间”与历史入口 → 继续上次草稿（有才显示）→ 一个明确的“开始自由创作”主入口 → 四个紧凑工具入口 → 今日选题 / 热点列表。首屏最多一个强调色主按钮，不让“个人 IP”“视觉设计”“自由创作”同时变成巨幅 Banner。

点击已有草稿进入 E06；点击选题进 E02；个人 IP / 获客营销按材料选择链路进入 E03；视觉设计与视频分析进入有场景提示的对话。定位报告通过“完善你的内容方向”辅助卡进入 G01，不能拦截所有浏览。

### 6.3 E06 编辑器与 E07 审核

顶部：返回、文档名或页面名、保存状态、更多。中间：大面积正文编辑区，来源材料折叠成可展开的引用条。底部：文字格式和 AI 改写入口；键盘出现时工具栏随键盘避让，正文可滚动。

AI 改写先展示对照：删除使用删除线 + 明确标记，新增使用底纹 + 明确标记；不能只靠红绿。固定底部“接受修改 / 放弃”，保留当前原文。自动保存失败用靠近保存状态的小条提示，允许继续编辑并重试；不得显示“已保存”。

### 6.4 D02 对话页

顶部标题与历史 / 更多 → 需要时显示一个上下文卡 → 消息流 → 附件预览条 → 输入区。AI 回复使用正文排版，长答案可阅读而非每条都套大卡片。引用材料以小卡 / 引用标记呈现，点击可核对。

工具执行用“正在读取材料”“正在生成内容”等短句，过程详情可展开。网络中断保留已输入文字和已返回内容；重试与发送新消息视觉区分。输入、录音、转写、发送是不同状态，不让一个麦克风图标同时承担互相冲突的含义。

### 6.5 F01 资产页

顶栏与搜索 → 已沉淀 / 影像 → 文件夹路径和筛选排序 → 内容列表 / 影像网格。统计概览、录音文件和外部世界放在紧凑二级入口区，不挤占大量列表空间。文件夹操作进入浮层；内容卡展示来源、标题、摘要、更新时间和未完成处理状态。

影像与笔记使用各自合适的密度。批量状态要显式显示已选数量、取消选择和动作含义；删除本地录音、删除卡内文件、删除笔记使用不同确认文案。

### 6.6 G02 数字孪生

“数字人 / 文件”切换保持语义明确。数字人视图上半部为粒子人或抽象数字形象，中部说明最近学习内容，下部“和数字分身对话”；文件视图展示材料、待审修改、正式版本。复杂修订放入独立审核面，不能挤在人物周围的小字标签里。

### 6.7 H03 设备管理

设备卡：名称 / 编号、电量、连接状态 → 当前录音 / 传输摘要 → 卡内文件与本地文件入口 → 自动同步设置。电量未知显示“暂不可用”，不是 0%。Wi-Fi 传输使用步骤条描述连接和文件进度，发生系统切换时明确下一步，但不声称自动处理系统授权。

## 7. 状态、反馈与通用组件规范

### 7.1 全局状态矩阵

| 状态 | 页面表达 | 操作与文案原则 |
| --- | --- | --- |
| 首次加载 | 与真实布局对应的骨架 | 不用假数据充当已加载内容 |
| 有缓存、正在更新 | 内容保留 + 轻量“正在更新” | 不整页清空、不跳回首页 |
| 空内容 | 说明为什么为空 + 一个首要行动 | 图谱“记录第一个想法”；资产“导入内容” |
| 无搜索结果 | 搜索词 / 当前筛选保留 | 清空筛选或修改关键词 |
| 操作中 | 相关按钮禁用 + 阶段说明 | 其他无冲突操作可继续 |
| 失败可重试 | 失败原因的用户语言 + 重试 | 保留输入和已完成部分 |
| 状态未知 / 待核验 | “正在确认结果” | 不当失败重复发起，不当成功提前跳转 |
| 部分成功 | 成功数 / 失败数 + 逐项结果 | 只重试可重试项，不掩盖失败 |
| 无权限 | 所需权限、用途、设置入口 | 可以返回，不能形成死路 |
| 只读 / 能力不可用 | 禁用原因或说明页 | 不出现可点击的假动作 |
| 成功 | 结果可见 + 下一步 | 保存、分享、打开任务各自准确表述 |
| 删除与不可逆操作 | 明确对象、范围和后果 | 默认安全按钮，删除需确认 |

AI / 云端任务进度只显示真实阶段。无百分比数据时用阶段与轻量等待反馈，不制作每秒递增到 99% 的假进度。新图谱节点出现不能暗示所有材料已经学习成功。

### 7.2 Figma 公共组件

必须先建组件再拼页面：TopBar、BottomNavigation、SegmentedControl、Primary / Secondary / Destructive Button、IconButton、TextField、SearchField、FilterChip、SourceBadge、StatusBadge、NoteCard、FileRow、FolderRow、TaskProgressCard、MessageRow、AttachmentCard、AudioPlayer、RecordingControls、GraphNodeLabel、GraphNodeCard、GraphToolbar、DiffBlock、EmptyState、InlineError、Skeleton、Toast、BottomSheet、ConfirmDialog、PermissionExplanation。

关键 Variant：主题 Light / Dark；按钮 Default / Pressed / Disabled / Loading；输入 Default / Focus / Filled / Error / Disabled；任务 Waiting / Running / Verifying / Succeeded / Failed / Partial；文件 Local / OnDevice / Transferring / Missing；录音 Ready / Recording / Paused / Finishing / Failed。

录音的波形表示录音活动，不用波形假装语音识别已成功。播放进度、录制时长和转写进度不能共用一个含义不清的进度条。

### 7.3 动效与可访问性

普通按钮 / 浮层动效建议 160—240ms；页面切换 220—320ms；图谱状态转换 400—600ms，仅作设计参考。禁止强烈闪烁、无限呼吸的全文标签和让正文一直位移的背景动画。

所有图谱核心操作保留按钮或列表替代路径。减少动态效果时停止自动旋转并缩短过渡，保留空间关系。放大字体后允许多行与页面滚动；底部主动作不遮挡最后一段正文。高对比、焦点、按下、错误和禁用状态均需有可见差异。

## 8. 需要连通的原型流程

1. **第一次获得价值**：A02 登录 → A04 基础定位 → A05 进度 → A06 声纹 / 设备可稍后设置 → B01 → C02 记录一个想法 → C12 / D01 查看内容 → 返回图谱看到对应内容入口。是否已形成图谱节点以真实任务完成为前提。
2. **从图谱到创作**：B01 旋转演示 → B03 选中 → D01 内容 → D02 讨论 → E06 创作 → E07 审核 → 保存 → F01 找到结果。
3. **把阅读变成资产**：F07 发现 → F08 栏目 → F09 阅读 → F10 选择沉淀位置 → F01 → D01。原始文章保持只读身份。
4. **一次录音卡采集**：H01 连接 → H02 录音 → H05 卡内文件 → H06 传输 → F06 本地文件 → C13 批量转写 → C12 → D01。另画断连与部分失败分支。
5. **一次 AI 创作**：E01 → E03 选材料 → E04 生成 → 暂离 → B05 消息 → E05 结果 → E06 编辑；另画失败后回到原任务。
6. **数字孪生受控学习**：D01 让数字孪生学习 / G03 导入 → G04 候选差分 → G05 讨论修订 → 确认并核验 → G06 正式版本。不得省略审核直接播放成功动画。
7. **会员购买恢复**：I03 选套餐 → 协议 → 支付交接 → 等待确认 → 权益生效；并列用户取消、失败、恢复购买与确认未完成。

所有流程都必须可返回起点，不依靠 Figma 画布外的说明才能找到下一步。核心流程中的错误分支至少有一个可操作出口。

## 9. Figma 文件组织与生成策略

建议 Pages：`00_Brief`、`01_Foundations`、`02_Components`、`03_Graph`、`04_Capture`、`05_Chat-Content`、`06_Creation`、`07_Assets-Discovery`、`08_Twin-Positioning`、`09_Device`、`10_Account-Onboarding`、`11_Prototype-QA`。

Frame 命名：`页面ID/中文页面名/状态/主题/宽度`，例如 `B01/知识图谱/Node-Selected/Light/390`。流程画板与注释区分开，用户界面上不显示内部页面 ID。各 Page 顶部放一段范围说明和生成批次，不把整份长说明贴进每个手机画面。

生成顺序：

1. 建立变量与组件；先做 B01、B02、B03、E01、E06、F01 的视觉样板，确认 3D 图谱是主角。
2. 完成知识图谱与内容 / 对话流程，补齐图谱全部状态。
3. 完成记录、导入、转写、设备与恢复状态。
4. 完成创作链路、资产、订阅与阅读。
5. 完成数字孪生、定位、登录、会员与设置。
6. 全量连原型、查状态、做小屏 / 大字 / 深色关键页适配。

每批只生成相应模块，继承同一套变量和组件。不要求一次指令生成所有页面；不能用重复首页占位来假装全量交付。主说明可作为 AI 的需求上下文，具体生成格式由使用的 Figma 功能决定；普通 Figma Design 画布不会仅因导入 Markdown 就自动变成可编辑页面。
