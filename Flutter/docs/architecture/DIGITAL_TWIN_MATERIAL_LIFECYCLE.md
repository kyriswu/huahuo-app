# 数字孪生材料生命周期接入

日期：2026-09-05。适用：Flutter 移动端；桌面端及后端不在本次修改范围。

## 两阶段确认入口补充

新的移动端入口统一为“材料入队 → 用户确认材料 → 生成候选 → 引用/对话修订 → 确认当前候选版本 → 核验正式版本”。状态触发条件、恢复边界和评分规则以当前实现、测试及 `docs/invariants/digital-twin.md` 为准。

- 已有自有笔记、保存副本、链接导入、文件导入、内录、外录及导入音频都能保存待确认意图；未确认不创建远端候选。
- 新文件导入将延迟确认标志随任务落盘，先普通入库，再排队。下文“上传回执中的蒸馏任务”流程继续用于既有自动蒸馏任务；不能对旧任务改写 complete 的冻结参数。
- 后端没有现成的材料队列/已有 Note 蒸馏接口；客户端队列按账号和 Workspace 持久化。确认材料后使用公开 Proposal API 和正式 Note 的 raw revision 创建三个 Profile 类别候选，不复制 Note，不运行测试脚本代替 API。
- 三类 Profile 对应五个逻辑文件视图；社媒定位继续使用原定位及既有服务端蒸馏路径。Proposal 是服务端候选、版本和差分对象，而非客户端写出的实体 Markdown 文件。
- 等级和完整度沿用后端定位画像评分，不按材料数量虚构增长。材料数、候选数、差分数和正式版本数是不同指标。
- 正式确认任务身份、材料来源/候选映射、已发送修订要求及服务端处理状态均持久化；未完成时继续核验，不能以等待结束冒充完成。

## 使用与恢复

从数字孪生页导入文件，或在普通文件导入页勾选数字孪生蒸馏。
单份材料导入完成后跳转到其审核范围；多文件保留逐文件结果页，成功项可以立即进入
候选审核或笔记，未完成项继续处理或重试。“材料记录”同时包含已受理但尚未生成笔记
的任务，这类任务进入原导入任务继续核验，而不是重新选择和上传文件。
确认只覆盖该材料的有变化候选，不吸收同一时间段其他材料或普通 Note 编辑提案。
“查看全部”返回完整数字孪生视图。确认完成后可在版本历史检查内容与来源。

公开 `GET /tasks/{taskId}` 不返回内部 resultRefs，不能据此猜测 proposalIds。
因此不照搬脚本的“时间窗口至少三条”，而是分页、按来源 Note 及 owner 精确筛选。
导入回执、确认身份跟随账号作用域保存；切换账号不复用其他账号的记录。
恢复时读取原确认任务，不重新上传文件或重复创建已受理的确认。

材料观察只在当前前台路由运行，三秒基础间隔、指数退避，最多 200 次后展示刷新入口。
停止观察不等于后台失败；只有服务端明确的失败状态才展示任务失败。
确认成功必须同时取得 `report_ready`、正的 appliedCount 和正式 version；部分失败保留逐项报告。

## 2026-09-05 用户路径审查后的恢复修复

| 边界 | 恢复行为 |
| --- | --- |
| 对象上传完成、complete 响应丢失 | 完成对象上传后先持久化 upload/resource 身份；重启后重放同一 complete，不再申请凭证和传输字节 |
| complete 已受理、Note 尚未生成 | 在任何 ingestion 查询之前持久化 ingestion/distillation 回执；本地文件丢失也可继续 GET 原任务 |
| 观察超时、网络结果不确定 | 保留 waiting 状态和恢复凭据，展示“继续查询”；不能宣称服务端失败 |
| ingestion 明确终态失败 | 持久化后端不可重试决定，不再提供只会重复读取同一失败记录的重试循环 |
| 用户确认前候选变化 | 弹窗冻结提案清单、版本、强 ETag 和材料范围；提交前重新读取快照，变化时要求重新审核；查看历史版本时禁止确认当前新版本 |
| 不认可、有变化或已过期的候选 | 用户可明确“不采用此候选”，不更改正式文件；生成失败、应用失败或过期时可显式重新创建候选 |
| 保存计划、查看历史 | 不推进材料观察的 generation、不取消材料轮询；写操作失败后恢复仍有效的观察 |
| 历史恢复 | 按 restore 返回的 proposalIds 建立独立审核范围，不再按原材料 Note 过滤；恢复只产生候选，不代表正式版本已经改变 |
| 恢复确认报告 | 先读取可能推进服务端状态的确认接口，再读取正式版本和历史；投影落后时保留报告及原确认身份，要求继续核验而不是重复确认 |

重新创建候选保留原始来源版本及公开 owner 元数据。新 Profile conclusion 继续使用
`newOwner` 契约；过期的既有 owner 只使用服务端已应用提案返回的 revision 身份，
创建时由服务端再次校验基线。若正式内容由其他路径更新，当前公开接口无法提供有效
基线，则明确提示暂不可重建，并允许放弃旧候选及更换补充材料；Flutter 不推导或伪造
服务端 revision ID。

后端通用 `/tasks/{taskId}/retry` 不支持数字孪生蒸馏任务，`rebase` 也只返回保守冲突。
因此前端不会把“刷新进度”包装为任务重试。源材料处理失败且没有候选时，说明需要
更换材料重新导入；已经产生的候选仍保留审核、拒绝或重新生成入口。

## 验证边界

使用定向 API、控制器、持久化与 Widget 测试验证接入及既有行为。
首次接入移动端四个定向测试文件共 65 项通过，共享上传客户端 5 项通过；
恢复修复在原测试文件内补充检查点、版本漂移、轮询隔离、历史恢复、投影追赶、
拒绝及重建和多文件按钮交互回归，不新增独立测试或源文件。
不执行原始脚本：其中登录、上传、Agent Run 和确认会写入远端业务数据，
与本工程的服务器只读约束不符。未进行真实账号端到端或实体设备验收。
